# 每日 Agent 任务日志设计

- 日期：2026-08-17
- 范围：每轮任务记录、时间追踪和分级日志
- 工作流等级：重大

## 意图与边界

每个 Agent 任务都需要可追溯，但日志成本必须与风险成比例。日志用于回答“何时执行、完成什么、修改哪里、如何验证、还剩什么风险”，不替代项目当前事实、复杂调查证据或 Git 提交历史。

## 调研来源与提取方法

- Keep a Changelog 强调记录应面向人、按时间组织、使用 ISO 日期，并反对把原始 Git 日志直接倾倒为变更说明。由此采用按日期文件、人工可读结论和禁止复制原始输出的规则。
- OpenTelemetry 将一次工作单元建模为包含名称、开始时间、结束时间、属性和状态的 Span。由此为每个 Agent 任务保留时间范围、等级、状态和分级属性，但不引入完整遥测系统。
- Microsoft 的 ADR 指南只记录影响结构、关键质量属性或难以回退的重大决策，并要求上下文、取舍、后果和状态。由此只让 L4/L5 记录详细决策与回退信息，低等级任务保持简短。

来源：

- https://keepachangelog.com/en/1.1.0/
- https://opentelemetry.io/docs/concepts/signals/traces/
- https://learn.microsoft.com/en-us/azure/well-architected/architect-role/architecture-decision-record

## 设计决策

- 使用 `docs/worklogs/YYYY-MM-DD.md`，一天一个文件，按执行结束顺序追加。
- 每条任务记录开始与结束时间、L0-L5 等级和明确状态；只在任务开始、结束各读取一次时钟。
- L0/L1 由根 `AGENTS.md` 直接写一行；L2-L5 才加载 `record-task-log`。
- 日志只复用本轮已有证据，写日志不触发测试、构建、知识同步、TRACE 或 Commit 文稿。
- 普通开发不读取历史 worklog；复杂证据进入 TRACE，当前事实进入对应概述文档。
- 多仓库任务在每个实际修改仓库记录，主要仓库完整、其他仓库简化。

## 验证

- 校验新增 Skill 和原有 Skill。
- 验证安装器能安装第五个 Skill，审计器能检测其缺失。
- 验证全新安装和 0.2.0 升级到 0.3.0 时保留项目专属规则。
- 使用本轮任务在独立流程包与 BookReader 中生成首个每日 worklog。

## 剩余风险

同一仓库存在多个并发 Agent 时，向同一日文件追加仍可能发生竞争。当前规则要求追加前只查看文件末尾并保留已有内容；若多 Agent 并发成为常态，再引入带锁的轻量记录脚本，而不是提前增加所有任务的运行成本。
