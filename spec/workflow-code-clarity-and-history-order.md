# 代码清晰度与历史顺序 Spec

## 元数据

- Spec ID 前缀：`WF-CLARITY`、`WF-HISTORY`
- 强度：完整
- 状态：已实现
- 最后更新：2026-08-17

## 目标

- 在不扩大普通任务成本的前提下，阻止本轮触达代码继续积累模糊命名、混合职责和失效注释。
- 让每日 worklog 和 TRACE 始终按真实时间自上而下排列，旧记录在上、新记录追加在下。

## 非目标

- 不为每个函数强制注释，不设置跨语言统一行数上限。
- 不在功能或缺陷任务中自动执行全仓重命名、拆文件或格式化。
- 不用静态结构审计替代代码语义、构建、测试或人工审查。

## 边界与约束

- 根 `AGENTS.md` 只保留低成本清晰度关卡，详细方法按需放入 `full-development` 的参考文件。
- 普通 L2 只处理与根因直接相关的误导名称或失效注释；跨文件/公共符号重构必须升级。
- 日志和 TRACE 继续按日期分文件；已无法恢复时间的历史记录保留在已知时间记录之前。
- TRACE 已发生的内容不覆盖；顺序修正只移动被错误插入位置的完整记录，不改写其事实。

## 行为与验收

### `WF-CLARITY-001`：每轮只检查触达代码清晰度

- 前置：任务新增或实质修改代码声明。
- 行为：收尾前检查本轮新增/修改的名称、文件归属、函数职责和相关注释。
- 结果：阻止新增模糊语义和混合职责，但不扩展为全仓整理。
- 异常与恢复：发现需要跨范围重构时独立报告或升级任务，不静默混入当前差异。

### `WF-CLARITY-002`：结构性整理按需加载详细指南

- 前置：用户明确要求命名/拆分/注释治理，或 L3/L4 变更出现多职责文件和难以命名的函数。
- 行为：读取代码清晰度参考，先做职责映射，再把行为不变重构与功能变化分开。
- 结果：按领域词汇和调用位置命名，按所有权/依赖/修改原因拆分，注释解释契约和原因。
- 异常与恢复：不得仅因超过固定行数或命中 `Util` 等词就自动拆分或重命名。

### `WF-HISTORY-001`：每日记录按开始时间升序排列

- 前置：当天 worklog 或 TRACE 已存在。
- 行为：新任务追加到文件末尾；较早任务在后续任务之后继续时，在末尾追加同编号“继续”任务块；较早 worklog 补录按真实开始时间移动完整记录块。
- 结果：自上而下始终为旧记录到新记录，不在文件顶部插入最新内容。
- 异常与恢复：并发或延迟写入造成倒序时，worklog 可移动完整记录到正确位置；TRACE 已发生的检查点不回填到旧块，而是在末尾追加继续事件。

### `WF-HISTORY-002`：所有任务使用独立标题

- 前置：记录任意 L0-L5 任务。
- 行为：L0/L1 使用单行二级标题，L2-L5 使用带正文的二级标题。
- 结果：简单任务仍是一行成本，并且不会在 Markdown 结构上从属于前一个复杂任务。
- 异常与恢复：历史普通列表项在确认时间后可转换为同内容标题。

### `WF-HISTORY-003`：审计器报告时间倒序

- 前置：项目存在 `docs/worklogs/YYYY-MM-DD.md` 或 `docs/traces/YYYY-MM-DD.md`。
- 行为：只读审计提取任务标题和 TRACE 检查点的可解析时间，并检查非递减顺序。
- 结果：发现后出现的时间早于前一条时审计失败并指出文件与时间。
- 异常与恢复：`时间未记录` 和跨日完整日期不伪造为当天时间；无法解析的普通正文不参与检查。

## 数据、接口与迁移（完整档按需保留）

- 数据与状态：worklog 任务标题和 TRACE 检查点是顺序检查输入，正文不是时间数据源。
- 接口与协议：L0/L1 标题为 `## HH:mm:ss–HH:mm:ss · Lx · 结果；文件：路径或无。`；L2-L5 标题保留可选 `T-HHmmss`。
- 迁移与回退：将 BookReader 当天两个 L0 和一个 L1 列表项转换为标题，并把 `17:07:19` 记录移动到 `17:13:04` 前；可通过 Git 恢复。
- 安全与隐私：不涉及生产数据、用户内容、权限或外部系统。
